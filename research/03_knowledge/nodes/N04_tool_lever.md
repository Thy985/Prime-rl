# N04 — 工具即杠杆？第一次 Harness A/B/C

## 1. 这里发生了什么

同一个模型、同一个任务集，只改一件事：**给不给 edit 工具**。
H_A = bash + edit；H_B = 只有 bash（移走 edit）；H_C = H_A 加完成条件绑定。
结果非常戏剧性：移走 edit，solve rate 掉了 44 分（n=1 的第一次读数）。
但把 H_C 复制到 n=32 后，效果**反转**了——撤回了 H_C 的主张。
最后稳定下来的说法窄而结实：**tool support（工具支持）是真实的杠杆；
难度是 task × harness 的交互，不是任务单方面的属性。**

## 2. 为什么走到这里

N03 找到了有信号的 operating point（绑定预算）。于是可以问一个
干净的因果问题：**改了工具的可用性，结果会不会变？**

## 3. 这里真正的问题

- Q1: 把 edit 工具拿走，agent 还解得出题吗？（答：解不出——−44pt。）
- Q2: 这个 44 分是稳定的吗？（答：H_C 的部分不稳定，n=32 反转。）
- Q3: 哪些失败是「根本没动手写」，哪些是「写错了」？（答：几乎没动手。）

## 4. 我原来怎么想

以为工具集就是杠杆本身——拿走 edit 慢一点、错一点，但方向明确。
也以为跑一次、两次就能说「H_C 更好」。

## 5. 我做了什么

- 3 个 harness × 3 次 run，最后 pool 到 n=32 per cell。
- 对同批轨迹做 mining：失败 case **从不 attempt 任何修改**
  （734496132）——约束性失败是 no-write，不是 bad-edit。
- H_C（completion-bound：有 pending change 时 episode 不能结束）
  一开始看涨（af3bddf12），随后复制 → **反转**，撤回了（6a1177c45）。
- 把命名固定成它真正配置的 harness（b6c1ad9a8，H_C 不再是通用名）。

## 6. 得到了什么

大白话：**给你一把锯子还是两把锯子，确实影响你能不能锯完——但「多给一个
条件」这类改动第一次测出来多好不重要，复制几遍才知道真相。**
移走工具的影响是真的（且很大）；「加完成条件」的影响是假的（n=1 噪声）。

## 7. 这改变了什么理解

原来：工具集是杠杆；单次 run 就能命名机制。
现在：只有 H_B 那种「大且稳」的效应能扛住复制；小效应必须复制后再命名。
**「复制先于命名」成为整个档案的模板**——后面 E06 的 2×2、E07 的 7 arms、
E08 的 n=60 全是这个教训的执行。

## 9. 专业术语

- action affordance：我的理解——环境允许你做的动作集合；
  本项目含义——edit 工具在不在手上；H_B 移走它是第一刀。
- completion bound：我的理解——「没改完不许结束」的规则；
  本项目含义——H_C 的机制，效果在 n=32 反转。
- no-write failure：我的理解——agent 从头到尾没写任何文件就结束了；
  本项目含义——失败的主形态根本不是「改错了」。

## 10. 可迁移的东西

CLI/工具设计的教训、RL 里 action space 设计的教训都适用：
**改动作空间是最粗暴的干预，效果大但「为什么大」常常是另一回事**
（这里是该动手没动手）。同时：任何第一次读数的效应，先复制再命名。

## 11. 还不知道什么

- known：H_B −44pt（大、稳）；H_C 反转（小、不稳）。
- inferred：失败主要是 no-write，不是 bad-edit。
- open：为什么模型「不动手」——没学会用工具？还是预算策略问题？→ N06 预算。
