# N08 — 预算形状效应：效果是预算的函数

## 1. 这里发生了什么

对 H_A/H_D 扫 max_turns ∈ {2,4,6,8}（同一 5 实例 grid，16 eps/cell）：
差距 **+6 → +32 → +19 → −6pt**。效果在 T=4 达到峰值，到 T=8 时
**反超消失（H_D 反而略输）**。在宽预算下，H_A 自己学会了
「inspect → edit → test → repair」（tstAft 50%、repair 12%）——
你以为 harness 教给它的验证行为，它在时间充裕时自己会长出来。

## 2. 为什么走到这里

N06 的量级随任务集缩水，另一个维度也该查：**效果是否依赖预算？**
如果 H_D 是「结构性改进」，什么预算下都该赢；如果只是「预算效率」，
那预算宽裕时它就该失效。

## 3. 这里真正的问题

- Q1: H_D 的价值是「结构性的」还是「预算效率的」？
- Q2: 预算很充裕时，H_A 会不会自己补上 harness 教的行为？

## 4. 我原来怎么想

以为 H_D 的增益是结构性的——无论给多少回合，分阶段引导都该有用。

## 5. 我做了什么

T ∈ {2,4,6,8} × {H_A, H_D}，5 gated django 实例，16 eps/cell。
对每条曲线看：gap 的形状、H_A 在 T=8 的行为（是否自发现验证+修复）。

## 6. 得到了什么

大白话：**分阶段引导是「回合不够花」时的省钱技巧。回合给够，自由模式
自己就会按同样的顺序干活，那引导反而开始拖后腿（多花回合在重读文件、
装包上）。**

## 7. 这改变了什么理解

原来：H_D = 结构性改进（任意预算有效）。
现在：**被否。** effect is budget-shaped：T=4 峰 (+32)，T=8 反超 (−6)。
H_D 的真实含义收窄为 **unit-budget efficiency**：把少量回合花得更值。
同时 T=8 的 H_A 自发现 verify+repair——**行为可以自发涌现，不需要教**。

## 9. 专业术语

- interaction budget：我的理解——允许 agent 和世界交互的次数；
  本项目含义——max_turns，扫过 {2,4,6,8}。
- budget-shaped effect：我的理解——效果大小是预算的函数，不是常数；
  本项目含义——T=4 峰值 +32pt，T=8 反超 −6pt。
- unit-budget efficiency：我的理解——同样预算下把资源用得更值；
  本项目含义——对 H_D 效果的最终理解框架之一。

## 10. 可迁移的东西

**任何「引导/脚手架」类干预都要画一条「效果 × 资源」曲线**：
便宜的干预在资源紧张时最值钱，资源宽裕时可能失效甚至有害。
适用于学习编程（脚手架）、产品引导、RL curricula、agent scaffolding。

## 11. 还不知道什么

- known：效应形状（+6/+32/+19/−6）；T=8 H_A 自发现 verify+repair。
- inferred：机制是预算效率而非结构性；H_A 的涌现行为与之对应。
- open：T=8 区域的正式研究从未做过（final_report 的未来工作 4）。
