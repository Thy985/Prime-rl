# Lessons for Future Research

Ten rules, each earned by a specific failure in this archive. The failure ID
points at `05_process/failure_ledger.md`.

## Instrument rules

**1. Audit the reward before the reward is rewarded.** A scalar that scores a
tampering repair above a genuine partial fix produces a study that measures the
verifier's blindness, not the agent's capability. (F01)

**2. Never compare numbers produced by two different protocols.** This is how two
headline conclusions were lost in a week of work. One serialisation, one verifier
version, one entry point — across training, inference and evaluation. (F02, F04)

**3. A classifier must not borrow validity rules from another mode.** A rule that
voids empty replies in a reply-mode setting silently deleted the failures that a
budget constraint had just created in a patch-mode setting. This was the only bug
close enough to inverting a conclusion to matter. (F07)

**4. A cliff must survive a failure-rate check.** Endpoint error rates and
contention will manufacture difficulty. Repeat before you pool. (F05, F06)

**5. When a metric is redefined, every page that quoted it must be revisited.**
Undefined and silent, this produced a 54% vs 25% gap that should have read
100% vs 100%. (F08, F12)

## Design rules

**6. Choose the operating point where signal exists before choosing the arms.**
A factorial at a budget where solve rates are 0–7.5% cannot answer the question it
was built to answer. (E06 Phase 6A)

**7. Pair on instances, not on aggregate rates.** The two results that survived
replication were both paired McNemar on the same 20 tasks. Unpaired aggregate
comparisons produced the single biggest overclaim in the archive. (F11)

**8. Buy the replication before naming the mechanism.** Every mechanism claim in
this study was first made at n=1 and every one was wrong or over-scaled. Naming a
mechanism from a single run is not a shortcut; it is how the study acquires
unnecessary phases. (F09, F11)

## Interpretation rules

**9. Do not read a contrast further than it supports.** A system-role vs
user-role comparison shows the two are not equivalent. It does not show that
interruption is causal. The narrowing cost two days and saved a false claim.
(E07, D15)

**10. File untested claims as untested.** An arm that never ran is not a negative
result. It is a missing dimension, and it should be labelled that way forever
until someone runs it. (F10, F14, H18)

## The one this archive did not learn in time

**Provider failure and model failure are indistinguishable in the harness log.**
An empty streaming response, a hung smoke test, and a model that cannot produce
tool calls all read the same way from the agent side. The correct diagnostic
order is: probe the endpoint directly, then the dependency chain, then the model.
It was done correctly twice and still cost the cross-model leg.
